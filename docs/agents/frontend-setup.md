# Frontend setup

- **Runtime:** React in the browser. Vite handles development and production builds. The frontend imports browser-safe common modules through their explicit package subpaths.
- **Commands:** `pnpm --filter frontend dev`, `pnpm --filter frontend build`, and `pnpm --filter frontend test`. Root checks cover this workspace too.
- **Composition:** `src/index.ts` defines the frontend App and dependency collections. Live and test roots construct `api`, the native Better Auth `auth` client, Storage, and Services; components construct UI Logic. Storage is empty until a feature needs persistence. Services hold browser capabilities such as `windowFocus`; live roots use `Live*` implementations and test roots use `Fake*` implementations that tests can drive.
- **React context:** `FrontendAppProvider` supplies an App to components. `useFrontendApp()` reads it. Create the live App outside component rendering; tests supply isolated Apps.
- **Logic props:** `FrontendLogicProps<StorageKeys, ServiceKeys, ApiKeys>` selects the dependencies a UI Logic needs. Feature UI Logic extends the common Logic base and supplies explicit initial state.
- **Owned Logic:** `useLogic({ LogicClass, deps, onError })` returns `{ logic, state }`. Keep `deps` stable with a memo or an existing stable object. Changing the class or dependency object replaces the instance. Initialization runs after commit; final cleanup is deferred by one microtask to allow React Strict Mode to replay effects. Unmounting before initialization finishes cancels it without reporting an error.
- **Hidden trees:** keep the owner above an `Activity` boundary that disconnects effects for a longer period. Our Logic lifecycle cannot restart after final cleanup; hidden children can use the observer hook instead.
- **Constructors:** Logic constructors and plugin factories must have no external effects. React can discard instances created during rendering. Start listeners, requests, and resources in lifecycle hooks, and pass `this.signal` to requests so unmounting cancels them.
- **Shared Logic:** `useLogicInstance(logic)` observes state without owning initialization or cleanup. A component or provider must own that instance's lifecycle. Multiple components may observe the same instance.
- **State:** the common Logic and LogicPlugin bases own their state and notify subscribers. React reads it with `useSyncExternalStore`; hooks do not replace state methods or merge plugin state into parent state. Observe a plugin separately with `useLogicInstance(logic.plugins.pluginName)` when a component renders its state.
- **Errors:** the owned hook reports initialization and cleanup failures through `onError`, or the default error reporter. Consumers can supply a feature-specific handler.
- **API:** `app.api` is the Hono client for routes under `/api` (for example `app.api.me`), with route and request types imported from `backend/api`. This import is type-only; backend runtime code stays out of the browser. Encode path parameters once with `encodeApiParam`; Hono substitutes them without encoding. Use `requireApiSuccess` for common HTTP error handling; it reads the shared `{ error: { code, message } }` body into `ApiRequestError`. First-party endpoints do not need a feature Service wrapper.
- **Transport:** live setup uses browser fetch. Relative paths are the default; `VITE_API_BASE_URL` can set another API location. The Vite development proxy forwards `/api` to the local Hono server. Test setup requires an injected fetch-compatible transport and cannot fall back to network fetch. Production static serving is not implemented yet.
- **Build order:** frontend development, type checks, and tests first build backend declarations and their common dependency. The explicit `backend/api` export supplies types; `backend/testing` is restricted to Node test code.
- **Routing:** React Router in Declarative mode. Live rendering uses `BrowserRouter`; tests use `MemoryRouter`. `/` has a counter Logic; `/examples/api/:encounterId?` has an API command Logic. Both are small examples for future feature pages.
- **Authentication:** `/login` is the public sign-in page. `AuthProvider` owns AuthLogic through `useLogic`; `/api/me` decides UI access, including the owner policy. The route gate protects all other pages and returns to the requested path after sign-in. AuthLogic clears the password after each attempt; it does not persist tokens or passwords. HTTP-only session cookies are managed by the SDK and browser.
- **Session changes:** both clients include credentials and share the same injected transport in tests. `apiAccessEvents` is a per-App typed event interface; a business API 401 clears UI access. AuthLogic subscribes to the `windowFocus` Service during initialization and checks the session again on focus. A 403 remains an operation error; the profile check reports denied admission on the sign-in page.
- **Declarations:** frontend `skipLibCheck` skips upstream declaration errors in the SDK (other-runtime imports and plugin types). Application sources and their use of imported client contracts are still checked.
- **Tests:** Vitest, React Testing Library, and jsdom cover app composition, typed API transport, routes, and Logic lifecycle. The [full application fixture](full-application-test-plan.md) also checks DOM content, UI Logic state, and an isolated database in one process.
